# 岛屿扩建方案设计文档（讨论存档）

> 状态：讨论中，未定稿。本文档记录 2026-08-30 关于「岛屿容量如何扩展」的完整讨论脉络，供后续详细设计时参考。
> 最后更新：2026-08-30
> 结论（当前方向）：**固定原始大小岛屿 + 房屋升级为多层小屋**，阶段演化方案暂挂起。

---

## 0. 背景与问题

cloudlet 是一座 3D 浮岛经营游戏。核心矛盾：

- 玩家持续建造房屋 / 工厂，**岛屿容量需要增长**才能装下更多建筑；
- 早期实现（v0.20）采用「`ensureIslandFits` 整圈放大岛屿半径」，建筑多了就把**整张圆盘**重建到更大半径。

**问题根因**：岛屿是 `CylinderGeometry` 的正圆形圆柱盘，建筑按同心环 `buildingPos` 往外排。一旦部分建筑超出当前半径，整岛就被放大 → 变成**又大又平的圆盘**，中心到楼之间是大片空草地，像硬币 / 盘子，显空、显呆、不美观。

**本质矛盾**：容量靠「半径横扩」实现，而横扩必然产生空旷大平板。

设计原则（用户明确）：**治愈系游戏，美与氛围是第一位的**，不能为了容量牺牲美观。

---

## 1. 第一轮：三个基础方案（均被否）

> 核心问题：这些方案本质仍是「一张平底盘」，只是换了轮廓或加了几层。

| 方案 | 思路 | 结论 |
|---|---|---|
| ① 阶梯式浮岛 | 2~3 层梯田 / 台阶，容量靠层数而非半径 | 体积感强，但与「平」同源 |
| ② 生长式半岛 | 建筑分组，每组对应岛缘伸出小半岛 / 平台 | 最自然，但工作量最大、易显碎 |
| ③ 有机不规则海岸 | 保留环形布局，圆盘点改噪声海岸不规则轮廓 | 只治标，不解决中间空旷 |

用户反馈：**三种方案都不是很美观**。

---

## 2. 第二轮：四个新方向（思路不同）

> 关键洞察：之前都「平」——真正好看的浮岛靠两样东西破局：**中央不要死草地**（用水 / 树占据视觉中心），或**陆地被打破成几块**（群岛 + 桥）。

| 方案 | 思路 | 评价 |
|---|---|---|
| ① 环礁岛（中央潟湖） | 岛是圆环，正中央一汪潟湖（复用喷泉池），建筑沿环排布，容量来自环周长（可内外双环）。中心是水不是空草地。 | 改动小、不空，推荐 |
| ② 桥接群岛（主岛 + 卫星小岛） | 主岛外飘 2~3 座小岛（住宅 / 农田 / 工厂），木桥相连。陆地被打破成多块，中间是海与桥。 | 最童话、最有记忆点，但桥几何 + 过桥寻路要调 |
| ③ 世界树岛（中央大树 + 环阶） | 岛中央一棵巨大故事书大树，村庄台地环绕树干层层展开。 | 视觉最惊艳，但工作量最大 |
| ④ 丘岛（保留轮廓 + 起伏地形） | 不换形状，加缓坡丘陵 + 小路，建筑依山错落。 | 改动中等、风险最低，但容量仍靠半径 |

用户反馈：也还不够好，并提出关键设想——**阶段演化**。

---

## 3. 关键转折：阶段演化设想（用户提出）

> 用户原话：「是不是可以考虑阶段升级，每个阶段用不一样的岛屿，这只是我的一个设想……这种治愈系游戏还是最重要的是美观治愈，我们再想想方案」

**核心范式转变**：岛屿不靠连续缩放，而是按进度**跳变到下一个精心设计的形态**。每次演化都是值得期待的「小高潮」，玩家看到的是 4 个各有美感的岛，而不是一个越长越尴尬的盘子。

**天然统一两层成长**：
- **微观**：单栋房屋升级（竖向生长）；
- **宏观**：岛屿整体跃迁到下一阶段（形态质变）。

---

## 4. 阶段演化 · 完整草案（已细化，未实现）

### 4.1 形态序列（四阶段）
| 阶段 | 形态 | 容量 | 演化里程碑（繁荣度阈值） |
|---|---|---|---|
| S1 | 萌芽小岛 | 8 | 起点 |
| S2 | 环礁岛 | 16 | ≥ 60 |
| S3 | 群岛 | 28 | ≥ 180 |
| S4 | 世界树岛 | 42 | ≥ 400 |

### 4.2 触发方式（已确认）
- **自动达里程碑触发**（非手动按钮）：繁荣度达阈值 → 自动演化，播放 ~2.5s 演化动画，解锁下一形态 + 更大容量。

### 4.3 繁荣度 / 人口计算
- 去掉 `building.level`（单栋不再升级）。
- `繁荣度 = Σ(各建筑基础值) × 阶段系数(1 / 1.4 / 1.9 / 2.5)`。
- 容量只由阶段决定。

### 4.4 建筑布局
- 每阶段一个 `layout(i, cap)` 把第 i 栋放到该形态的预设穴位：
  - S1 萌芽：1 环 r≈3.2，8 穴，中心池 + 树；
  - S2 环礁：外环(10) + 内环(6) = 16，中心潟湖；
  - S3 群岛：主岛 2 环(16) + 卫星×2(各 6) = 28，木桥；
  - S4 世界树：3 环(8+14+20=42)，中心大树。
- 演化时旧建筑按新阶段穴位**平滑迁移**（动画），不丢失。

### 4.5 演化动画分镜（~2.5s）
旧岛下沉 / 碎裂淡出 → 新形态从海中升起（环礁陷湖 / 群岛升小岛 + 桥 / 世界树大树生长）→ 建筑逐个弹跳落位 + 花瓣光点 + 镜头缓推。

### 4.6 自由模式兼容（用户追加要求）
- 保留「自由模式」给**当前用户**：阶段演化做成新玩家默认，老存档沿用 v0.20 连续扩张岛（进度不丢）。
- 数据模型：
  ```
  GameState {
    ...
    islandMode: 'free' | 'stage'   // 老存档→'free'，新存档→'stage'
    stage: number                  // 1..4，仅 stage 模式用，默认 1
  }
  Building.level  // 不再使用
  ```
- `save.normalize` 补 `islandMode`（老存档 `'free'`）、`stage`（默认 1）。
- 设置里可切模式：自由 ↔ 阶段（切换时重建岛体，建筑按目标模式重排）。
- 迁移：切阶段时按当前建筑数反推最小满足容量的起始 stage，避免丢建筑。

### 4.7 待拍板小点（当时未决）
1. 阶段系数 / 阈值数值是否满意；
2. 自由模式是否仅老用户默认、还是新用户也可在设置里选；
3. 里程碑指标：繁荣度（已选）/ 建筑数量 / 累计发货订单；
4. 建筑重排方式：固定穴位按序入位（已选）/ 保留相对位置。

## 5. 最终方向调整：放弃阶段演化，改回「固定岛 + 多层升级」

> 用户最终判断：扩岛不好看，阶段演化也先搁置。**新方案 = 岛屿固定原始大小 + 房屋升级成多层小屋**。
> 用户原话：「把当前测试环境上扩容的岛缩小成原始大小……多出来的房屋规划升级现有房屋，支持升级后变成二层小屋」

**设计意图**：容量由「竖向升级」提供，而非「横向扩岛」。与已实现的 `economy.populationOf/prosperityOf` 按 `b.level` 线性放大天然契合——升级一栋 = 同 footprint 容量翻倍。

### 5.1 已实现改动（仅本地，未部署）
1. `src/render/world.ts`：删除 `ensureIslandFits`（自动扩岛方法）及其在 `syncBuildings` 的调用；岛屿固定为 `ISLAND_RADIUS=9`，不再整圈放大。
2. `src/render/meshes/structures.ts`：`makeHouse` 重写——按 `level` 堆叠楼层（1 层平房 → 2 层小屋 → 3 层），每层有窗 / 门、层间小檐、顶层四坡屋顶；去掉原整体放大 + 装饰环。占地面积不变，只往高长。
3. `src/ui/panels.ts`：升级卡片 meta 改为「升为 N 层小屋」。
- `BUILDING_MAX_LEVEL=3`（actions.ts）；`upgradeBuilding/upgradeCost` 升级链路 v0.20 已完整。
- `npx tsc --noEmit` 通过；dev server(HMR) 运行中，结构改动需硬刷新看效果。

### 5.2 已知遗留点
- `buildingPos` 仍按同心环排（ring2 r=8.2 落在岛上，ring3 r=10.1 会超出岛缘）。测试存档若已有 >30 栋建筑可能悬空；设计意图是「少建多升」，如需要可后续加建造上限或重建存档。
- 阶段演化方案（萌芽 → 环礁 → 群岛 → 世界树）暂作**挂起 / 存档思路**，未删除，将来若想做可再捡起。

## 6. 待后续详细讨论的开放问题

1. **悬空风险**：固定岛后建筑数超限如何处理（建造上限 / 动态吸附到最近穴位 / 压缩环距）？
2. **二 / 三层小屋的视觉细节**：窗格、阳台、颜色分层是否到位，是否需要屋顶花园等装饰。
3. **阶段演化是否彻底放弃**，还是保留为「未来大型版本」的可选路线？
4. **多层升级的繁荣度曲线**：当前线性放大是否足够，是否需要级差（如 Lv2 给 1.8×、Lv3 给 3×）。
5. **部署**：VPS 生产仍停在 v0.18（登录修复）；v0.19 / v0.20 及本次多层改动均未部署，需上线再走 rsync + pm2 流程。
